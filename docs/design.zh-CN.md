# Deskpad Vision 技术设计

## 当前目标

第一阶段不识别外部桌面，而是把 MacBook 原生触控板左右两侧的掌托平面变成两个扩展触控区。
系统依赖键盘和触控板定位 MacBook 底座，因此屏幕打开角度发生变化时不需要重新人工标定。

为了把定位问题和接触识别问题分开验证，当前默认使用“食指进入区域”作为移动开关：进入左右任一
区域即控制相对移动，离区立即停止。早期验证用的捏合模式和个性化接触概率都保留为可选模式；
接触模型暂不作为默认开关，待更多训练和误触测试后再启用。

## 从网球轨迹项目吸收的工程方法

本项目借鉴的是朋友网球项目的开发思路，不是复制其代码。网球系统不会让 YOLO 直接回答“落点是
什么”，而是把视频预处理、检测、跨帧跟踪、球场标定、物理约束、事件提取和可视化逐层拆开；
Deskpad Vision 采用同样的分层原则：

| 网球系统 | 本项目 |
| --- | --- |
| 球场线 + Homography + Camera Pose | 电脑三边与触控板四边 + 规范平面映射 |
| 球/球员 Pose 检测 | 食指尖与 21 点手部关键点 |
| Kalman、ByteTrack、Optical Flow | 多帧校准融合、锁定式对齐、状态迟滞；目前未直接引入这些算法 |
| 物理轨迹优化 | 消失点、平行/垂直方向、包含关系、凸性和漂移约束 |
| 落点/反弹事件 | 入区、移动、接触、抬起、点击和拖拽事件 |
| 轨迹与热力图 | 校准预览、实时叠加层和训练质量报告 |

核心取舍是“强模型低频、轻模型高频”：DeepLSD 只在校准时提供线段证据，随后由物理几何求解器
选出满足约束的电脑和触控板；运行时只做锁定式平面对齐、MediaPipe 手部追踪和小型状态机。这样
避免每帧重新检测边框造成抖动，也让失败原因可以被报告和复现。

训练同样遵循可验证的分层流程：

1. 按校准哈希、物理侧和手别保存原始会话，禁止不同几何或左右手混训；
2. 分别采集 AIR、TOUCH、SLIDE、LIFT，并补充边界附近、不同光照和手腕角度的困难负样本；
3. 从关键点姿态、相对深度、关节角度、平面速度、局部纹理/阴影和背景差分提取特征；
4. 物理左右侧分别训练，连续帧按时间块划分训练/验证，避免相邻帧泄漏造成虚高指标；
5. 先限制误触率再选择召回率最高的阈值，未通过质量门的模型不落盘；
6. 实时概率再经过连续帧确认、非对称迟滞和离区抬起容错，最后才生成交互事件。

后续若引入自训练 YOLO/分割或单目深度，它们仍只提供边线、手或深度先验，不直接决定是否点击；
新模型必须在独立会话上优于现有误触率，才能替换当前路径。

## 校准 V2：强模型只运行一次

校准 V2 不再从键盘宽度按比例“画”电脑或触控板。它先采集一段无手短序列，检查采集期间是否
发生相机运动，再融合成一张时间中值图减少传感器噪声，最后由 DeepLSD 产生真实线段证据。
先融合、后做一次离散线段选择，可以避免多张近似图在相邻反光边之间跳转。模型只在校准时运行；
实时手部追踪不加载 PyTorch。

几何求解器从所有候选线中联合选择：

1. 电脑底座的左侧边、右侧边和前沿；
2. 实体触控板的左、右、上、下四条边；
3. 被电脑两侧边裁剪后的掌托深度带。

左右侧边在透视图里本来就不平行，也通常不与前沿呈 90 度。因此约束不直接施加在图像角度上：
两条机身侧边先给出纵深方向消失点，触控板两侧必须通过同一个消失点；前沿、触控板上沿和下沿
属于另一个平面方向。这样才能表达“物理上平行、垂直”，同时允许图像呈梯形。

每个候选解还必须通过外框跨度、触控板居中程度、四边凸性、边缘覆盖率和多帧角点抖动检查。
总置信度低于门槛时不会写入 profile，也不会覆盖上一次可用校准。通过后额外保存带三边、触控板
和掌托区域的预览图及 JSON 质量报告，便于肉眼复核。

## 数据流

```text
摄像头
  │
  ├─ 镜子边界检测 ──> 有效图像遮罩
  │
  ├─ 长边线候选 ──> 纵深方向参考（不冒充电脑外框）
  │
  ├─ 键盘 ORB 特征 ──> RANSAC 单应矩阵 ──> 固定参考坐标
  │                                      │
  │                                      v
  │                          参考图坐标 ──> 物理平面坐标
  │                                      │
  └─ MediaPipe 手部关键点 ──> 食指坐标 ────┤
                                         v
                              平面区域命中 + 平面内位移
                                         │
                                         v
                                相对移动 + Quartz 事件
```

## 镜子边界

启动时从多帧灰度图计算时间中值，减小移动手部造成的影响。只在图像下部搜索长水平边，并结合：

- Canny 边缘与概率 Hough 直线；
- 垂直 Sobel 响应的横向稳健统计；
- 长度、水平角度以及与行梯度峰值的距离；

得到裁切位置后向上保留安全边距。裁切线以下的像素会被置黑，不参与特征或手部推理。用户可用
`[` 和 `]` 微调。

## 旧版一次性参考标定（回退路径）

用户在无手画面中捕获一张参考图，在浏览器标定页确认或拖动两组四角点：

- 紫色四角对应原生触控板的左上、右上、右下、左下。程序先从 CLAHE 增强画面中寻找
  上下长边，再沿候选左右斜线积分水平梯度，得到有真实像素证据的触控板四边形；检测失败时
  界面会明确标记为默认候选，绝不把比例估算冒充成识别结果；
- 青色虚线是程序通过 Canny、Hough 线段和稳健直线拟合得到的透视方向参考。它可能来自键盘
  或其他长边，因此不被当作电脑机身的真实外框；
- 橙色四角是实际可用掌托平面的边界。用户只需在首次标定时把它确认到比键盘更宽的机身外沿；
- 红线对应镜子固定下边界。

由此保存：

- 图像尺寸和裁切线；
- 触控板透视四边形；
- 可用掌托平面的透视四边形；
- 键盘参考区域；
- 用于平面坐标变换的单应矩阵输入。

参考图在裁切线以下会被清空，避免保存无关的人像内容。

这次人工确认不是每次运行都重画。运行时使用键盘上的稳定特征求单应矩阵，并把已经确认的触控板
和电脑外框一起投影到当前画面，所以屏幕角度变化后仍能自动跟随；只有镜子安装位置明显变化才需
重新标定。

橙色电脑底座带状区域被映射到一个 `1800 × 625` 的规范平面，紫色触控板作为内部几何校验和
左右分区边界。扩展区先在规范平面中生成，再投影回参考图，所以它们不仅符合透视关系，还会被
电脑真实左右边框裁剪，不会越到桌面或镜中人体区域。

## 运行时定位

参考图只在键盘区域提取 ORB 特征；当前图在有效画面内提取特征。通过 Hamming 距离、双近邻比例
测试和 RANSAC 求得：

```text
当前摄像头坐标 ──H──> 参考图坐标
```

接受结果需要满足：

- 至少 18 个 RANSAC 内点；
- 中位重投影误差不超过 4.5 像素；
- 变换尺度和三角形面积通过基本几何检查。

定位失效后立即重置移动锚点，并停止所有系统鼠标输出。

旧版 profile 仍会把参考平面的四边形通过 `H⁻¹` 投影到当前画面。

V2 profile 改为“启动重锁定 + 锁定几何 + 漂移报警”：启动后的多帧键盘匹配只估计平移、旋转和
统一缩放，补偿参考图与实时画面的固定偏移；多帧一致后把这一受限变换锁定。系统不再把狭窄键盘
区域估出的完整单应矩阵外推到掌托，也不逐帧修改变换，所以检测框既能贴回当前边缘，又不会随
RANSAC 噪声摆动。后续键盘匹配只检查画面是否偏离已锁变换；连续多帧出现真实位移时立即冻结
鼠标，并要求重新运行 V2。

## 手部和移动

MediaPipe 输出一只手的 21 个关键点。食指尖先通过 `H` 变换到参考坐标，再通过橙色电脑底座
四边形定义的第二个单应矩阵变换到规范平面坐标。区域命中和相对移动全部在该平面中计算，从而
消除同样物理距离在画面远端和近端呈现不同像素距离的问题。

当前默认交互不使用手势开关：食指尖进入任一左右区域后立即开始相对移动，离开区域立即停止。
捏合模式作为可选方案保留，其距离使用掌宽归一化：

```text
pinch_ratio = distance(thumb_tip, index_tip) / distance(index_mcp, pinky_mcp)
```

可选捏合模式的启用和释放使用不同阈值，并要求连续两帧确认。相对移动使用低通平滑、速度增益、
单帧最大跳变量和区域切换重新锚定。真实鼠标输出必须通过 `--enable-pointer` 显式开启。

镜面画面中的左右与用户物理左右相反，因此运行时和数据中明确保存两套名称，例如
`image-left / physical-right`。这个位置语义转换与鼠标方向设置彼此独立。当前实测安装只需要
反转 X 轴，Y 轴保持原方向；运行时仍可用 `x`、`y` 键分别切换。

## 接触识别

单目深度模型可提供有价值的先验，但不能单独决定“接触”：黑色反光掌托、手部遮挡和毫米级距离都
会造成误差。实现时将把深度模型输出与平面几何、时间信息和局部阴影共同使用。

`deskpad collect-contact` 默认自动引导物理右侧和物理左侧各完成
AIR、TOUCH、SLIDE、LIFT 四类采集。每一步先给 6 秒准备，再累计 5 秒有效帧；手部丢失、平面未
锁定或食指处于错误一侧时计时自动暂停，因此不依赖无法获得焦点的 OpenCV 数字键。每条记录包含
完整的 21 点原始手部关键点，并提取：

当前里程碑只训练右手：电脑物理左右两侧都使用右手食指。样本和模型明确保存
`physical_hand=right`，以后加入左手时会使用独立数据和模型，避免两种姿态分布互相污染。

采集可按类别独立增量执行：`deskpad collect-air`、`collect-touch`、`collect-slide`、`collect-lift`
是四个顶级独立命令，每次只采集对应动作，并依次覆盖物理右、左两侧；重复同一命令会累加该类别
样本。窗口使用不同颜色的大号中文横幅显示唯一允许的动作，并在写入前交叉校验命令标签、协议标签
和样本标签，不一致时直接中止。只有左右两侧四类样本都达到最低数量才自动训练。
`deskpad reset-contact` 不永久删除数据，而是把现有样本、模型和报告整体移入带时间戳的
`contact-archive`，保证新一轮训练完全不读取旧批次，同时仍可人工恢复。
也可用 `deskpad reset-contact --label lift` 只归档一种动作并保留其他类别。

LIFT 有专门的离区容错：准备阶段要求指尖真实位于目标彩色区域并记录平面锚点；进入采集后锁定
原来的物理侧，允许关键点在限定平面距离内因抬起视差离开彩色多边形，并继续计时。超过距离门限、
手部丢失或几何失锁才暂停。运行时同样在已确认 TOUCH 后短暂保留原区域，以便离区的抬起仍能形成
RELEASE 和 TAP，而不会被当成追踪丢失直接取消。

- 食指尖相对 MCP、DIP 和中指尖的 MediaPipe 深度；
- PIP/DIP 关节角度；
- 参考平面中的速度和图像纵向速度；
- 与无手参考图的局部差分；
- 指尖周围的纹理梯度和上下、左右亮度不对称。

平面定位是否可信不作为普通特征交给分类器，而是更严格的总开关：一旦定位、手或有效区域丢失，
接触状态直接失效。

数据只保存在本机 profile 下，并用参考图哈希隔离不同校准。当前使用带正则化的个性化逻辑模型
输出接触概率，保留验证样本选择阈值；误报率或召回率不通过质量门时不会保存模型。

由于同一只右手跨到电脑另一侧时姿态分布变化明显，训练阶段按物理左、右区域分别拟合模型，运行
时根据 `physical_zone` 选择相应模型。实时结果经过非对称迟滞和连续帧确认后成为
`AIR → TOUCH → RELEASE` 状态，短暂高概率不会触发 TOUCH。

`--control-mode contact` 把 TOUCH 用作相对移动开关：首次接触只建立锚点，持续接触滑动才产生位移。
短时间、低位移的 TOUCH→RELEASE 被解释为 TAP；先静止保持约 0.6 秒再移动被解释为拖动。默认只在
画面预览，真实移动需要 `--enable-pointer`，真实点击和拖动还分别需要 `--enable-click`、
`--enable-drag`。丢失手部、平面或区域时立即取消手势；若鼠标键已经按下则强制发送 mouse-up，防止
系统停留在按住状态。

# Deskpad Vision 技术设计

## 当前目标

第一阶段不识别外部桌面，而是把 MacBook 原生触控板左右两侧的掌托平面变成两个扩展触控区。
系统依赖键盘和触控板定位 MacBook 底座，因此屏幕打开角度发生变化时不需要重新人工标定。

为了把定位问题和接触识别问题分开验证，第一阶段使用拇指与食指捏合作为安全的移动开关。
真实接触、轻触点击和拖拽将在定位与延迟稳定之后加入。

## 数据流

```text
摄像头
  │
  ├─ 镜子边界检测 ──> 有效图像遮罩
  │
  ├─ 键盘 ORB 特征 ──> RANSAC 单应矩阵 ──> 固定参考坐标
  │
  └─ MediaPipe 手部关键点 ──> 食指坐标 + 捏合状态
                                  │
                                  v
                           左/右区域状态机
                                  │
                                  v
                         相对移动 + Quartz 事件
```

## 镜子边界

启动时从多帧灰度图计算时间中值，减小移动手部造成的影响。只在图像下部搜索长水平边，并结合：

- Canny 边缘与概率 Hough 直线；
- 垂直 Sobel 响应的横向稳健统计；
- 长度、水平角度以及与行梯度峰值的距离；

得到裁切位置后向上保留安全边距。裁切线以下的像素会被置黑，不参与特征或手部推理。用户可用
`[` 和 `]` 微调。

## 一次性参考标定

用户在无手画面中捕获一张参考图，并框出原生触控板。由此保存：

- 图像尺寸和裁切线；
- 触控板矩形；
- 键盘参考区域；
- 触控板左右两侧的有效区域。

参考图在裁切线以下会被清空，避免保存无关的人像内容。

## 运行时定位

参考图只在键盘区域提取 ORB 特征；当前图在有效画面内提取特征。通过 Hamming 距离、双近邻比例
测试和 RANSAC 求得：

```text
当前摄像头坐标 ──H──> 参考图坐标
```

接受结果需要满足：

- 至少 18 个 RANSAC 内点；
- 中位重投影误差不超过 4.5 像素；
- 变换尺度和三角形面积通过基本几何检查。

定位失效后立即重置移动锚点，并停止所有系统鼠标输出。

## 手部和移动

MediaPipe 输出一只手的 21 个关键点。食指尖通过 `H` 变换到参考坐标，然后判断属于左区、右区或
无效区域。

捏合距离使用掌宽归一化：

```text
pinch_ratio = distance(thumb_tip, index_tip) / distance(index_mcp, pinky_mcp)
```

捏合启用和释放使用不同阈值，并要求连续两帧确认。相对移动使用低通平滑、速度增益、单帧最大
跳变量和区域切换重新锚定。真实鼠标输出必须通过 `--enable-pointer` 显式开启。

## 下一阶段：接触识别

接触估计器将使用 8–12 帧的时间窗口，输入包含：

- 食指尖相对深度与变化速度；
- PIP/DIP 关节角度；
- 参考平面中的速度和减速度；
- 无手背景差分；
- 指尖局部外观和指尖—阴影间隔；
- 手部与平面定位置信度。

模型输出接触概率，并由带迟滞的 `AIR → CANDIDATE → TOUCH → RELEASE` 状态机转换为移动、轻触
和拖拽。验收时优先降低误点击，其次才是减少漏检。
